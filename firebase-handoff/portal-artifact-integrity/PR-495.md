# PR — Coverage gate classifier, D-111 repair fence, sweep cursor fix, status-0 retry class

Closes #495

## What ships

### 1. Classifier — `unclaimed` reason (the relabel)
`classifyMiss` gains an `unclaimed` bucket, ordered **after** `unsigned` and
`deletedInElation` and **ahead of** `pendingSweep` / `ingestable`, so a
deleted-upstream document for an unclaimed patient still reads
`deletedInElation`. The determination is **passed in** from the audit's existing
unclaimed-with-pending computation — the pure module never re-derives it.

The bucket is excluded from `ingestableDenominator` / `ingestableCoveragePct`
(the gate measures documents that should be ingested **now**) and emitted in
both `byReason` and `residualByReason`.

Justification, confirmed in the repo: `claimAccount.js` step 9b sets
`status: 'active'` and step 9c *awaits* `backfillElationReports` /
`backfillElationLetters`, which per #372 / D-119 mint `internalUid`, upload the
PDF and verify the header. The 147 docs load on claim; the nightly skip is
intended D-080/D-081 behaviour.

### 2. D-111 fence — both ends
- **Audit side (primary):** `auditArtifactCoverage` stops enqueueing repair rows
  for patients classified `unclaimed`, the same shape as the existing skip for
  `unsigned` / `deletedInElation`.
- **Sweep side (backstop):** `repairOne` calls the shared `ingestEligibility`
  before any Elation fetch. Not a local `status === 'active'` check — a
  dependent never claims, so an adult-only rule would fence out exactly the
  chart-backing documents `minorChartBacked` measures. Minors resolve through
  the guardian-proxied path (`dependent.isMinor` + >= 1 guardian with
  `status: 'active'`). Missing patient doc = hard skip; a Firestore read error
  **fails open** so a blip cannot stall repairs.
- Skipped rows are **inert, not destroyed**: `skippedReason` written, no failure
  increment, no park, so a mid-cycle claim makes the same row eligible next
  pass. Runs report an `ineligible` counter. Existing queued rows are left in
  place, not purged, so the population stays observable.

### 3. D-308a — the scheduled sweep did not drain the queue
The cron claims a **date-keyed** run id (`cron-YYYY-MM-DD`) and `driveRun`
resumed from the cursor stored on that run doc. The first run of the day
finished with the cursor parked at the end of the queue; a manual re-trigger
re-opened the same run, started *after* that cursor, read an empty page and
reported `complete` without touching a row — precisely the live evidence from
the primed minor (`updatedAt` unchanged, `repairedAt` null, `failures` still 1).

Fix: a run whose prior status is `complete` starts a **fresh pass from the top**
(cursor and counters reset), and a completed run stores no end cursor.
`adminRunArtifactRepairSweep` with a new runId was never affected and remains
the reliable ad-hoc driver.

### 4. D-308a follow-on — `elationStatus: 0` becomes retryable
Status 0 is our own client's code for network/timeout/abort — the same class as
`ARTIFACT_FETCH_TIMEOUT`, which self-heals off-peak. It previously fell through
to the hard-failure path, so five flaky fetches parked a retryable row.

It is **not** added to `TRANSIENT`: a pure transient defers the run without
charging the row, which would let a genuinely unreachable document retry
forever. Status 0 now defers the run **and still charges an attempt**, so the
row gets its full retry budget across runs and the attempt that reaches
`MAX_FAILURES` still parks and still raises the parked alert.

## Wording of D-308 (confirmed, not provisional)
> Rostered-but-unclaimed patient docs are excluded from the ingestable gate
> denominator; ingestion is deferred to account claim. Repair enqueue and the
> repair sweep both fence on ingest eligibility. The 147 queued rows were
> **enqueued but never driven** (same-day cursor resume, D-308a) — not skipped
> at an eligibility gate; there was no gate.

Evidence: all 147 rows `parked: false`, `failures: 0`, single batch
`firstSeenAt 2026-09-04T07:15` (three timestamps within 3s), `missReason:
"ingestable"`, `source: "audit"`. Plus the primed-minor re-trigger returning an
untouched row.
